## 翻译与回答约定

- 每题 `id` 为题包 ID 加三位原题号，例如 `work_values_20_001`、`favorites_100_100`。编号与原题逐一对应；每题 `source_ref` 均包含完整原页面 URL 和原文题号。题号用于定位页面列表，不伪造原站不存在的题目锚点。
- 工作价值观保留每题两端的含义与顺序，涵盖例行与变化、协作与独立、效率与质量、稳定与挑战、个人与社会价值等。两端只用于引导开放文本回答，可以兼顾、分情况说明；原作者在「回答スタイルについて」也明确表示不必选定其中一端。
- 喜好问卷的原文「好きな」译为「喜欢」，不额外强化为「最喜欢」。保留特定对象、品牌与日本文化背景，不替换成本地明星、平台、作品或习俗。原文第 100 项是给读者的留言邀请，按原貌收录，不改造成新的喜好问题。
- 人和小机均可跳过不适用、不熟悉或不愿回答的题。小机无需虚构身体、感官体验或职业经历；题目不改写为 OC／人设创作，也不要求扮演人类。相关约定放在题包 `adaptation_note`，不逐题添加引导词。
- 仅作开放式对话素材，不设置评分、阈值、人格结论或诊断；本批只提供 JSON 与来源文档，不将长篇原文写入 MCP Guide。

## 验收方法

1. 对照两个原页面的有序列表，核实编号连续且分别为 20、100，逐题检查译文对象、限定语和顺序。重点复核以上文化对象及两套的首尾题。
2. 用标准库 JSON 解析检查顶层字段恰为 `topic_id`、`title`、`description`、`author`、`source_url`、`license`、`license_url`、`adaptation_note`、`questions`；元数据均为非空字符串，`questions` 为数组。
3. 每题字段恰为 `id`、`text`、`source_ref`，值均为非空字符串；ID 按原题号连续生成且跨两包唯一；每题出处匹配对应来源 URL 与原题号；总题数为 120。
4. 审查实际文件 diff 并运行 `git diff --check`。这是静态题库验收，不表示后端加载、网页或 MCP 已经接入。
